## Tests — Developer Guide

This document describes how to run unit and end-to-end (E2E) tests for the project, how coverage is produced, and how CI runs tests.

Overview

- Unit tests: Vitest (frontend using `jsdom`, backend using `node`).
- E2E tests: Playwright (`@playwright/test`) running against the dev server.
- Coverage: generated by Vitest using the `istanbul` provider and written to `coverage/`.

Run tests from repository root

- Always run tests from the repository root. This ensures both frontend and backend runners use the repo-level `node_modules` and the Vite cache directory configured in `vite.config.js`.

Unit tests

- Backend tests (node):

```bash
# run backend tests (uses vitest backend config)
npm run test:backend --silent
```

- Frontend tests (jsdom):

```bash
# run frontend tests
npm test -- --run --silent
```

Coverage

- Generate coverage locally:

```bash
npm run test:coverage
```

- Notes:
  - The repository uses `vitest` with `coverage.provider: 'istanbul'` (see `vitest.config.js`).
  - Coverage output is written to `coverage/` and `coverage/.tmp/` — these are ignored in git via `.gitignore`.
  - For CI, we run coverage with `--maxWorkers=1` to avoid worker timeouts on some runners.

E2E (Playwright)

- Install browsers (one-time / CI):

```bash
npm run e2e:install
```

- Run the dev server (in a separate terminal) and then run tests from repo root:

```bash
# start dev server
npm run dev

# in a separate shell, run e2e
npm run test:e2e
```

- Playwright config highlights (see `e2e/playwright.config.cjs`):
  - `baseURL` / `url` bound to `127.0.0.1:5173` to avoid `localhost` IPv6/IPv4 resolution issues on some hosts.
  - `webServer.command` starts both backend and frontend using `concurrently` when running tests.
  - `reuseExistingServer: !process.env.CI` — in CI the web server is started by Playwright; when running locally, an existing dev server will be reused.

CI behaviour

- The repository contains a reusable workflow at `.github/workflows/build-reusable.yml`.
- The CI (`.github/workflows/ci.yml`) calls the reusable workflow with the following inputs for PRs:

```yaml
with:
  run_videos: false
  run_e2e: true
  upload_artifact: true
  do_deploy: false
```

- Meaning: PR builds will run ESLint, Prettier checks, unit tests, coverage, and E2E; artifacts (`coverage/` and `test-results/`) are uploaded for debugging failed runs.
- The Pages deploy workflow calls the same reusable workflow but with `run_e2e: false` to keep the deploy step fast.

Tips & troubleshooting

- Always run tests from repo root to prevent `frontend/node_modules/.vite` being created.
- If Playwright tests fail with connection errors on Windows, check that the dev server is bound to `127.0.0.1` and not `::1` (IPv6 localhost). The config binds to `127.0.0.1` already.
- If Vitest coverage run hangs or times out in CI, run with `--maxWorkers=1`.
- If you need to debug failing CI runs, enable `upload_artifact: true` in the caller workflow to get `coverage/` and `test-results/` artifacts.

Commands quick reference

```bash
# install deps
npm ci

# run unit tests
npm test

# run coverage
npm run test:coverage

# install playwright browsers
npm run e2e:install

# run e2e
npm run test:e2e
```
